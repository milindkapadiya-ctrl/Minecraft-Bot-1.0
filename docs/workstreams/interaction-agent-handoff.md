# Interaction body handoff for a future autonomous agent

Status: **body contract and integration proposal**, 2026-10-27. This document aligns the Interaction workstream with the larger event discussed in the Codex chat **“Plan an autonomous AI bot.”** That plan calls for a slow goal selector, a fast local tactical policy, and deterministic Minecraft tools with a structured observe → decide → act → verify loop. It explicitly found that no neural policy or autonomous decision loop exists yet. This document specifies how the existing Interaction body can be consumed later; it does not implement an AI policy or approve new shared interfaces.

## Available bounded capability

`collectObservedDirt(context, runner, target, signal)` in `src/integration/observed-collection.ts` accepts one dirt or grass-block target previously returned by visible inspection. It uses the current session's real three-view scanner, plans at most one flat waypoint from each completed scan, acquires a fresh visible support block state for each guarded `walk_to`, checks observed stable arrival, and obtains a new scan before any later waypoint. At cardinal adjacency it delegates to `collectNearbyDirt`, which re-looks, re-inspects the exact block and state ID, uses guarded server-confirmed digging, and compares dirt inventory counts. When needed, that routine considers one guarded descent into the freshly visible hole and waits briefly for pickup. The route is limited to three flat waypoints and the route stage has a 20-second deadline; the collection stage has its own 12-second deadline. Both are cancellable and fail closed.

The supervised CLI exposes this as `inspect`, then `collect_route <index>`. `ActionRunner` remains the sole action/control owner. The exported function is callable from a future local coordinator, but the repository does **not** yet provide a policy-facing selector, autonomous loop, model, episode recorder, or goal scheduler. This capability is specifically for nearby dirt/grass on certified flat ground; it cannot be described as general resource gathering, maze traversal, or unattended Survival play.

## Proposed policy-to-body boundary

1. A future coordinator obtains a compact, legitimate observation from the existing inspection/scanner path. Visible target identity must be tied to that observation and current session. Unknown or occluded terrain stays unknown. The model must not create arbitrary block coordinates or state IDs, query loaded chunks directly, or receive a raw Mineflayer bot/world object.
2. The policy chooses one bounded intent from the capabilities actually implemented at that time, or chooses to wait/reobserve. For the current Interaction slice, the only route-and-collect intent is one visible dirt/grass target. The coordinator resolves the model's choice to the **trusted target from the current inspection**, validates material and freshness, and passes that copied target to `collectObservedDirt` with a cancellation signal. This target-selection wrapper is **proposed, not implemented**.
3. The body executes one sequence and returns a structured result. The coordinator records the observation reference, chosen intent, start/end session identity, result, and measured inventory delta. These fields are a proposed episode record, not a current file format or training dataset. A model-generated success label cannot replace measured evidence.
4. After any failure or uncertain outcome, the coordinator discards the old route/target authority, obtains a new observation, and makes a new decision. No automatic unbounded retry, speculative next waypoint, or direct raw-control fallback is allowed. Cancellation and immediate safety continue to work without a remote model call.

This boundary leaves strategic goal selection and local neural-policy representation open, as the other chat recommended. Inputs, action vocabulary beyond current body tools, network/model framework, training method, reward and evaluation design require a separate coordinated decision. Any OpenAI API integration must first satisfy the repository's current-official-guidance, usage-accounting, and persistent spending-preflight requirements.

## Result interpretation for the future coordinator

| Body result                                                             | Safe interpretation                                                                                                                                              |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inventory_increase_observed` plus positive `collection.evidence.delta` | A relevant inventory count increased during the guarded interval. It is evidence of pickup, not proof of item provenance if other pickups occurred concurrently. |
| `not_observed`                                                          | Dig/optional landing may have happened, but a relevant inventory increase was not measured. Do not mark the resource objective complete.                         |
| `refused`                                                               | Do not infer progress. `reason`, optional `route`, and optional `collection` identify the failed boundary; reobserve before considering another action.          |
| `cancelled` or `timeout`                                                | Stop the current decision. Await stable state and new evidence before issuing another action.                                                                    |

`collection.evidence.status === "unverified"` is never collection success, even if a block appeared to change or an inventory count changed during failed cleanup. A route failure preserves the `RouteResult` (`movementCode`, segment index and reason when available); a collection failure preserves dig/movement codes and inventory evidence. Delivered world/lifecycle changes during scanning or travel invalidate the pending route. Client event monitoring cannot prove that **every** server change was observed; this remains a reviewed consistency limitation.

## Validation and remaining gates

- Offline integration runs the production scanner, pure planner, canonical action controller, visible movement port, guarded dig and inventory verifier against a controlled fake. Two flat course directions reach an inventory-confirmed pickup. A delivered block update during scanning or walking stops before digging and releases controls/listeners. These are **fake-world results**, not protocol or real-physics evidence.
- Existing nearby collection has narrow live Survival evidence: server-confirmed grass digging, guarded descent with dirt-count increase, and multiple digs with no observed increase. Two fresh isolated localhost 26.1 fixtures on 2026-10-27 added adjacent sand digging with sand 0→0 (`not_observed`) and a later empty inventory read, then `collect_route` on adjacent grass with `steps: 0`, successful guarded dig/descent and dirt 0→1 retained by a separate inventory read. Attempts needing a route refused on a delivered invalidation or insufficient observed target support. No live `walk_to`, planned-route pickup, or varied integrated course is verified. Both bots and servers exited normally; the user's original server directory was untouched.
- Before treating this body as reliable for the larger event, run a coordinated safe Minecraft 26.1 fixture with actual target and route-support coverage, one flat **walked** pickup, one modest layout variation, independent inventory read, and full bot/server cleanup. Preserve normal Survival/no-cheat conditions. Do not convert the offline result or the adjacent live pickup into a live walked-route claim.
- For broader autonomy, Ethan/HQ must settle scan freshness and client-observed consistency; Will/HQ must review route/arrival ownership and live walking; HQ must define the larger event's starting conditions, objective, duration, permitted assistance and success metrics. Crafting, food, combat, recovery and progression remain separate body milestones before long unattended play.
