# MCBOT-AUTONOMY-FOUNDATION-02 — trusted inspection boundary

## Pre-implementation decision

Verified clean foundation-01 HEAD `90385f8824317ef7f0d3a8775f002849924ce5d1`; both `944ec84` and `dbc9806` are ancestors. Dedicated branch: `codex/mcbot-autonomy-foundation-02`. Offline only; no live or desktop operations.

Private composition can authenticate an operation scope to the Bot with `operationCheckpoint`, execute genuine `scope.run({type:"inspect"})`, retain the reservation through copying and pure selection, and reject delivered lifecycle/world changes and exact sampled pose differences. The scope's admitted-child epoch authenticates action history **only while that reservation is alive**. A local invalidation counter denotes delivered events, not a world revision. Session callbacks and canonical runner/logger construction are trusted application composition, not hostile plugin boundaries.

There is no supported global action-history subscription or atomic reservation transfer. `collectObservedDirt` unconditionally starts its own `runOperation`; calling it within inspection's operation returns busy. Releasing inspection first permits an independent inventory/look/movement action, including an away-and-return pose, before body admission. Telemetry is not a supported admission capability and replacing runner methods would bypass shared ownership design. No current-position comparison closes this gap.

Implementation decision, recorded before code: implement genuine reserved inspection, private copied selection and opaque single-use diagnostic intent; implement a request boundary that consumes authentic intents but refuses `ownership_transfer_unavailable`. Never invoke collection after releasing the reservation. Keep existing simulated coordination and verification available, with no claim that it closes the real handoff. Demonstrate both ownership alternatives in production-path fake tests. This is the task's explicitly permitted alternative outcome, not completed inspect-to-body integration.

## Shared-interface proposal — pending review, not implemented

Owners: ActionRunner/session, Perception, Navigation and Interaction. Consumers: trusted inspection composition and observed collection. Reuse the existing private `collectOwned(context, scope, target, signal, navigation)` implementation in `src/integration/observed-collection.ts` through a reviewed internal collaborator accepting an authenticated `OperationScope`, while retaining the public collector's own-reservation wrapper and its result/diagnostic normalization. This is a change in supported admission authority, not permission to bypass the private boundary by casting or duplicating collection code. A single outer operation could then reserve inspect → private selection → fresh guarded collection → retained inventory. It must authenticate Bot/scope, preserve child epoch checks, cancellation, cleanup and deadlines, and never expose the internal collaborator to CLI/model input. Review total time budgeting (current body reservation maximum32s), retained-inventory ownership and exact admission freshness before implementation. Test independent/reentrant action rejection, revoked/foreign scopes, post-cleanup authority, and the full CourseBot sequence without replacing safety guards. No API change is made here.

## Implemented boundary

`src/autonomy/trusted-inspection.ts` exports `TrustedInspectionTrial`, `InspectionPreparation`, opaque `InspectionIntent` and structured `InspectionRequestResult`. The class takes the trusted session reader and existing canonical runner; it has no observation/result injection port, body callback, raw controls or world-read implementation. `prepare()` is single-use, including concurrent calls and failures. It starts monitoring before reserving and invoking the genuine production inspect child. `operationCheckpoint(scope, bot)` rejects a foreign runner and authenticates exactly one admitted child before selection.

Own Bot/entity, session ID/active state, dimension, exact position, yaw/pitch and eye height are bound locally. Before/after action snapshots must match the expected pose. Only bounded result fields (at most25 blocks) are copied before invoking the unchanged pure selector. Copies of the selected target leave the class as diagnostics; the real association remains in JavaScript private fields and uses opaque object identity, never a caller ID/revision. Forged objects and foreign/replayed intents refuse. An authentic request is consumed before checks, including cancellation/failure; no retry occurs. A session-reader exception during an event callback permanently invalidates even if the reader subsequently recovers; review found this edge case and a regression covers the repair.

All delivered block/chunk changes conservatively invalidate, even distant ones. Death, respawn, forced movement and end invalidate. `physicsTick`, `move` and `game` sample exact pose/session state. Listener removal invalidates and is checked again at boundaries. Invalidation is sticky: sampled away-and-return position/camera changes cannot restore validity. Outer abort, explicit disposal and a monotonic1000ms deadline revoke the association. Expiry/disposal/request/failure remove owned listeners; the automatic timer bounds abandoned-intent monitoring. Production runner retains its existing physical cleanup and operation-revocation behavior.

The selector's `revision` field is populated only by the **private delivered-invalidation count**, initially zero; any delivered invalidation refuses before selection. It is not an invented world revision, public capability or global action epoch. The1000ms budget begins before inspection (conservative age), not after it. No timing policy is relaxed.

## Deliberate limits and tests

No listener can detect an undelivered event, an unobserved synchronous away-and-return state assignment, or session replacement/restoration between samples. A bare runner close or independent action after reservation release also lacks a supported history capability. Tests explicitly show an independent inventory action succeeds after `prepare()`, without changing pose/world state. Accordingly **every authentic request refuses `ownership_transfer_unavailable`, with zero body requests**. This is a fail-closed request boundary, not a functioning collection adapter or production gameplay feature.

The real `ActionRunner.runOperation` → `scope.run(inspect)` → `local.inspect` → private copy → pure selector sequence runs against CourseBot. Tests cover genuine selection/ranking, absent candidates, missing/malformed/oversized results, snapshot mismatch, forged/replayed/foreign intents, result/output mutation, foreign Bot/runner/entity/session/dimension, exact sampled away-and-return, delivered changes, lost monitoring, cancellation, concurrent calls, expiration, blocked timer delivery, disposal and stale callbacks. Reentrant independent inventory is busy during the reservation. The actual `collectObservedDirt` entrypoint is busy when nested inside it. These distinguish the unresolved ownership gap from a fixture limitation.

A separately labeled production-body test exercises actual guarded collection, scanning, planning, controlled fake physics, confirmed dig and a separate canonical inventory read: dirt0→1, retained1. It deliberately does **not** pass a trusted intent to collection and does not claim the missing end-to-end boundary. Existing `OfflineCollectionTrial` tests retain contradiction/unchanged inventory, retained-inventory failure, body refusal/cancellation/timeout and late callback coverage. They are simulation-port evidence, not proof of authentic body admission. Full trusted inspect → actual body → retained verification remains blocked by the shared-interface decision above; body/retention cancellation tests through that missing connection are not claimed complete. Simulated inventory changes do not prove item-by-item provenance.

## Activation and safety review

No production entrypoint imports the new class. No CLI, session lifecycle, ActionRunner, scanner, body, navigation, dependency or lockfile implementation changed. No new scheduler, retries, API or learned policy. Pure selection still has no Bot/world/control access. The request boundary cannot reach collection at all. The existing two DEMO-02 attempts remain independent and unconsumed; no Minecraft/server/world/OBS/GUI/screenshot/recording activity occurred.

Future activation requires reviewed implementation of the authenticated scope-sharing contract, a passing complete controlled-fake workflow including independent retention and cleanup, and separately authorized supervised CLI composition using the real session lifecycle. Importing this class alone cannot enable collection. The next substantial milestone is that bounded ownership/admission integration, not additional target policies.
